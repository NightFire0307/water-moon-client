# 技术决策记录

## 选片数据同步方案

### 方案选型
- 方案A：实时同步 优点：可以实时获取客户的选片状态，适合协作选片 缺点：实现比较复杂，需要维护客户端和服务端之间的连接，需要处理断开和重连逻辑
- 方案B：HTTP请求 优点：可以控制同步频率，兼容性好，适合单用户选片场景 缺点：可能会丢是最新的状态，需要标记脏数据，否则会重复发送请求

### 最终方案
- 采用方案B，前期的开发维护成本比较小，暂时没有多人协作选片需求


## 预选阶段

### 预选状态
- 已选择：已经标记要的照片
- 已排除：已经标记不要的照片
- 待处理：还未标记的照片

### 预选提交时不同的状态处理
- 已选择的数量 = 套餐指定数量 && 待处理 = 0 -> 正常提交
- 已选择的数量 > 套餐指定数量 && 待处理 = 0 -> 提示超出部分会有额外费用 -> 正常提交
- 已选择的数量 < 套餐指定数量 && 待处理 = 0 -> 提示当前选择的少于套餐指定数量 -> 正常提交
- 已选择的数量 = 套餐指定数量 && 待处理 > 0 -> 提示是否自动将剩余的x张照片标记“排除” -> 正常提交
